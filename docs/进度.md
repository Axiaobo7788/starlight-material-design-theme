## 当前仓库维护问题

### 1. 依赖项需要刷新

2026-11-02 检查时，`package.json` 的版本范围整体较新，但 `pnpm-lock.yaml` 仍锁在一批较早的小版本。

优先策略：

1. 先做兼容范围内的 patch/minor 更新；
2. 跑完整验证；
3. 再单独评估 major 更新；
4. 不为了“追最新”把 TypeScript / pnpm 等工具链直接跨多个 major。

GitHub Actions 也存在明显版本滞后，应单独做一批维护升级并检查迁移说明。

### 2. 文档存在历史漂移

已确认的旧信息：

- `src/content/docs/guides/implementation-plan.md` 仍声称 runtime dynamic color picking 未包含，但 0.2.2 已实现；
- `docs/RELEASE_CHECKLIST.md` 仍有大量“第一次发布 / 0.1.0”语境，与当前 0.2.2 不一致；
- 部分设计状态记录停留在 2026-06，需要补充 0.2.1 / 0.2.2 后的当前事实。

这类冲突应优先修正，因为它会直接误导后续 agent。

### 3. Peer lower-bound 仍需要验证

`docs/RELEASE_CHECKLIST.md` 中仍保留：

- Astro 最低支持版本；
- Starlight 最低支持版本；

需要实际安装最低版本组合验证后，才能把 peer 范围视为稳定承诺。

### 4. 发布配置仍有人工维护项

npm trusted publishing / OIDC 等配置属于仓库外部维护状态，不能仅凭源码断言已经完成。

除非有明确任务，不要：

- 把主题改成完整组件框架；
- 引入 Tailwind 到核心路径；
- 引入 `@material/web` runtime；

- 在维护依赖时顺手重做设计；
- 未经要求 bump version / tag / publish。
