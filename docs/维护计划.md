## 批次 A：兼容范围内依赖刷新（已完成）

目标：只做当前 semver 范围允许的 patch/minor 更新。

步骤：

1. 运行 `pnpm outdated` / 等价检查；
2. 检查 root package、workspace package、creator template；
3. 更新 lockfile；
4. 不跨 major，除非单独说明；
5. 跑：
   - `pnpm run typecheck`
   - `pnpm run check:contrast`
   - `pnpm run build`
   - `pnpm run verify:package`
   - `pnpm pack --dry-run`
   - `pnpm run test:screenshots`
6. 记录最终版本矩阵。

优先关注：

- Astro
- Starlight
- Playwright
- Node types
- Sharp
- Astro check

## 依赖升级决策原则

### 可以直接进入维护批次

- patch
- 已在当前 semver range 内的 minor
- 没有 migration note 的低风险工具升级
- 安全修复

### 单独处理

- major
- Node / pnpm / TypeScript 大版本
- Astro / Starlight major
- 会改变截图渲染、DOM、CSS 的核心依赖
- GitHub Actions major

### 不做

- 只为了版本号好看而升级；
- 一次跨多个 major 且没有实际收益；
- 为了消除 lockfile diff 而破坏 peer compatibility；
- 测试失败后无分析地更新 snapshot。

## 完成定义

一次维护批次只有同时满足以下条件才算完成：

- 代码/配置更新完成；
- 相关测试通过；
- 视觉回归已检查；
- `docs/进度.md` 已更新；
- 如有长期事实变化，`docs/记忆.md` 已更新；
- handoff 中写明剩余风险。
